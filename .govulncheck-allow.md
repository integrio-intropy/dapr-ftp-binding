# Accepted govulncheck findings

Each entry must say why the finding does not apply, and be removed as soon as a
fix is reachable.

## GO-2026-5242 — Dapr: Service Invocation path traversal ACL bypass

**Module:** `github.com/dapr/dapr` @ v1.11.0-rc (pulled in transitively by
`github.com/dapr-sandbox/components-go-sdk`).

**Why it does not apply:** the vulnerability is in the Dapr *runtime's* HTTP
service-invocation path. This component imports only
`github.com/dapr/dapr/pkg/proto/components/v1`, the generated protobuf stubs for
the pluggable-component gRPC API, and never runs the sidecar's service
invocation. The call traces govulncheck reports are `fmt.Sprintf` reaching the
generated messages' `String()` and `ProtoReflect()` methods, not the vulnerable
code.

**Why it is not simply fixed:** upgrading `github.com/dapr/dapr` to v1.15.14
drags in a `components-contrib` whose metadata API has changed incompatibly
(`metadata.DecodeMetadata` no longer exists), and the pluggable-components Go
SDK is compiled against the older contrib interface. The version is pinned by
the SDK, not by us.

**Re-check when:** the Go SDK is updated, or we stop depending on it.
